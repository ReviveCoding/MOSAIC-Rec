2026-09-20: Predeclare embedding-level missingness, mismatched image embeddings and reduced behavioral support as development robustness interventions. Raw-cover blur/crop remain held by source-rights ambiguity. The existing M1-M7 gate receives only behavioral support as context; for fixed support it cannot learn a weight response to an image-content mismatch that it does not observe. Availability masks can force a branch weight to zero, but that is deterministic exclusion rather than learned reliability detection. Unless a separately developed, qualified gate passes the specified directional tests before freeze, describe these models only as adaptive multimodal fusion and keep `RELIABILITY_PROMOTE` unsupported.

2026-09-20: Replace the 30-second idle watcher with `scripts/wait_for_free_gpu_freedom.sh`, requiring five minutes of continuous absence of GPU compute processes and known unrelated neural workers before attempt 2. It launches only the distinct FREEDOM retry, not the rest of the GPU queue. This remains a conservative local coordination measure, not a reservation against unrelated processes starting afterward.

2026-09-20: Before the queued common FIT-visible BPR pilot ran, code review found its negative sampler used all FIT item IDs and each user's complete FIT history for every earlier event. That would make negative eligibility depend on later FIT observations. Correct it under the same DEVELOPMENT protocol before any result: at each event sample only among items first observed in FIT by that timestamp, excluding the current item and the user's interactions before that event. Events with no eligible negative are omitted from training. The original earlier BPR receipt is untouched and remains a noncomparable pilot. A known-answer temporal test passes; the corrected pilot has not yet run.

2026-09-20: The original SASRec/GRU4Rec development pilot code selected training negatives from source-wide first-observed item IDs. Some FIT-hidden cold IDs could therefore have received negative item-embedding updates despite zero positive FIT support. Preserve those pilots and their overall scores as historical internal observations, but disqualify their cold-start interpretation and require a corrected rerun before comparator qualification. Future sequence training now builds negative availability from FIT_VISIBLE only, asserts no controlled-cold ID enters that pool, and still uses the declared source-wide first-observed proxy only for evaluation candidates. This is a pre-lock DEVELOPMENT repair, so protocol p1 remains valid; no old receipt is overwritten.

2026-09-20: The same sequence trainer had excluded only the most recent 20 history items from negative sampling, despite retaining the full past history. Future runs now exclude every item previously observed for that user by the event time. This prevents a distant prior positive from being sampled as an unobserved negative; the historical pilot remains unchanged and unqualified.
